What this does NOT mean:
This is not a finished general-purpose blocks IDE. Most block editing still uses
the source inspector. Community pack installation, multi-file navigation,
package imports, advanced expression blocks and Python are not implemented.

Current implementation:
sourceModel.js lazily loads Babel and records source slices and nested bodies.
sourceBlocks.js renders them and reuses unchanged top-level Blockly objects.
app.js coordinates code edits with revisions, debounce and paused block editing
while text is invalid/pending. Events are disabled during programmatic rendering.
fileStore.cjs uses native-dialog-selected file capabilities, conflict checks,
atomic writes and one backup; sidecars contain only disposable layout data.

Performance, stated accurately:
- Babel reparses the active file after a typing pause. Not incremental parsing.
- Unchanged top-level visual trees are reused; changed sections are rebuilt.
- No project-wide scan while typing; ZCS is used only on file open.
- Saving writes the complete source atomically. No accumulating AST cache.
- Undo holds at most 40 snapshots with roughly 4M characters aggregate budget.
- Current file limit 1 MB. Background parsing and larger projects remain future work.

Known limits:
- No dedicated nested views for every construct (e.g. switch cases/expressions).
- Syntax validation cannot prove scope, imports, types or runtime behavior.
- Matching unchanged node text preserves IDs, not arbitrary semantic identities.
- JS is case-sensitive: preserve identifiers and capitalization exactly.
- App-managed userData/sessionData/temp/crashDumps use .zbc-runtime on D:;
  operating-system-managed storage cannot be controlled by this app.
- Project .npmrc directs npm cache/logs into .zbc-runtime/npm-cache.
- Old project.json/localStorage formats are not automatically migrated.
- Old modules remain on disk as inactive reference; current UI imports only
  sourceModel/sourceBlocks/runner. Old pack scaffolding is not a stable API.
- The 800KB Vite warning threshold predates this repair. It does not shrink the
  bundled Blockly library. Babel remains a separate lazy-loaded chunk.
